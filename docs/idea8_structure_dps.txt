idea8 使用说明：事件结构驱动的 UNet 主干特征在线修正
更新：2026-10-25

2026-10-27 离线目标替换诊断：
默认 --guidance_target_source event 保留事件预测目标；显式 gt_oracle 仅在有 GT、
guidance_steps>0 的离线评测启用，禁止与 --inference_only 混用。GT 通过结构权重
保存的同一 image_structure 算子产生两尺度目标，仅替换目标，原事件结构损失权重 W、
特征掩码 M0=mean(W)、保护区域 K0=1-mean(W) 固定。run_config 显式记录 GT 使用。
--sample_manifest 继续保留全数据集索引/种子；日志保存 latent/W/M0/K0 哈希供跨组核对。
--save_float_predictions 保存未量化预测与评测 GT，用于结构/纹理配对分析。
GT 目标结果是离线机制诊断，不能当作可部署方法性能，也不是严格性能上界。

1. 已实现的计算路径

本分支基于 idea4 提交 101182b068d10f49a1e780da4467de02c1cf3c27。
原 OSEDiff + Event LoRA（residual_cross_attn）仍负责生成初始增强结果。
新增独立事件结构预测器：正负分离的 10 通道事件 → 两尺度软边缘 S 和置信度 C。
推理在最后一个 UpBlock 之前，对主干特征执行 h = h0 + M * delta。
delta 与 h0 同为 [B,C,H,W]，可修改全部通道，不经过 LoRA rank=4 瓶颈。
delta 是当前样本的临时张量；生成器、VAE、事件编码器、LoRA、结构头权重均冻结。

由 VAE 输出图像计算固定 Gaussian + Sobel 软边缘，与事件预测的结构比较；
结构误差通过 VAE、scheduler 映射、UNet 后段反传到 delta。后段 Event LoRA
的 cross-attention 会重新计算，其 Query 仍可随主干特征变化。
候选必须在最终 clamp 图像上改善总目标，并满足输出变化预算，否则减半步长重试；
全部重试失败则返回上一个已接受结果，至少保留初始增强结果作为回退。

这是一种 DPS 启发的结构约束优化，不是原始 DPS 的严格后验采样。
不比较前后两帧亮度变化；边缘损失下降也不等于恢复了真实纹理。
扩散时间步仍固定为一个，开启修正会执行多次 UNet/VAE 前向和反向。
当前版本完整重放 UNet，没有实现后段缓存加速；forward_calls 记录包括重试的实际次数。

当前正步数支持：Stage3、refinement 关闭、batch=1、256×256 方形输入。
含 decoder-refinement 权重的 checkpoint 不用于此版本的正步数修正。
steps=0 则保持既有 baseline 能力，包括旧 Stage4 的 legacy_fused/CGDRS 路径。
结构头未训练或未完成置信度阶段时，程序拒绝开启指导。

3. 数据、时间和场景划分

数据沿用仓库的 SDE 结构：
  DATA_ROOT/scene_name/low/<数字名称>.png
  DATA_ROOT/scene_name/normal/<数字名称>.png
  DATA_ROOT/scene_name/low/<事件片段>.npz
或 low/lowlight_event.npz（完整事件流）。
RGB/GT/事件片段仍按各自数字名称排序后的 index 配对，不要求同名。
现有数据读取器扫描 PNG；JPG 数据需要先统一数据格式。

原 5 通道 cLoRA/refinement 视图保持既有语义。结构视图单独读取原始 [t,x,y,p]，
前 5 通道为正极性、后 5 通道为负极性；同点同 bin 的正负事件不会相消。
时间先以 int64 相减后再分箱。结构数据拒绝有符号预计算 voxel
和已经丢失绝对时间精度的 float32 时间戳。
计数归一化固定为 clamp(log1p(count)/3, 0, 1)，不做逐样本最大值归一化。
RGB、GT、三种事件视图共享同一次裁剪/翻转/缩放参数。

默认 STRUCTURE_MODE=idea4_compatible（2026-10-25 更新）：
优先复用按排序 index 配对的事件分片；没有分片则使用原读取器，从完整事件流中
按前/后相邻低光帧时间戳截取，严格排除窗口两端。第一帧/最后一帧使用事件流首/末时间作为外边界。
共享空间裁剪后，以剩余首/末事件时间范围均分为 5 个 bin，末事件归入最后一个 bin；
同一时刻事件归入第一个 bin，空事件输出零。分箱公式与 idea4 的相对时间 float32 比值一致。
正负分开计数为 10 通道，不采用生成器的 active_bins 合并；保留结构头原有 log1p 归一化。
不需要设置 STRUCTURE_TIME_UNIT / STRUCTURE_WINDOW_BEFORE / STRUCTURE_WINDOW_AFTER，
也不使用 manifest/offset；遗留固定窗口参数应清除，避免误认为这些参数在兼容模式生效。
完整流截取仍要求事件与图像文件名时间戳单位/时钟域一致。各样本的物理窗口长度可能不同，
空间裁剪可能改变分箱边界；相邻帧窗口可能包含未来事件，不宣称因果实时推理。

可选 STRUCTURE_MODE=fixed_window，必须核对传感器元数据后显式提供：
  STRUCTURE_TIME_UNIT=ms/us/ns
  STRUCTURE_WINDOW_BEFORE=<目标时刻之前的整数 ticks>
  STRUCTURE_WINDOW_AFTER=<目标时刻之后的整数 ticks>
窗口为 [t_ref-before, t_ref+after)。允许 after=0 的因果窗口。
若 after>0，使用了未来事件，不能宣称因果实时推理。
单位声明不自动转换文件内容，事件与目标时间必须已在同一单位和时钟域。

STRUCTURE_REFERENCE=filename（默认）：low PNG 名称必须是真实目标时间戳。
若名称仅为帧序号，应使用 STRUCTURE_REFERENCE=manifest，提供 STRUCTURE_MANIFEST CSV：
  scene,frame_id,t_ref,time_unit
  scene_a,000001,1234567890000000,ns
frame_id 必须与 low 文件 stem 一致；示例数值不代表实际数据的单位或偏移。
STRUCTURE_TIMESTAMP_OFFSET 默认 0，在两种 reference 模式下都加到 t_ref。

固定窗口模式优先使用完整事件流；若只有分片，需自行确认每片覆盖目标窗口。
没有传感器录制起止元数据时，诊断明确标记 recording_bounds_unverified。
首/末事件并不等于录制边界；当前实现不会假装已验证窗口完整。
模式、窗口配置、单位、极性布局、算子参数随结构 checkpoint 保存，测试继承这些配置。
新预处理配置版本为 v2；缺少 mode 的旧 v1 checkpoint 仍按 fixed_window 读取。
续训/置信度初始化显式指定不同 mode 会报错；换模式必须从头训练结构和置信度，不能静默复用。
manifest 模式的测试数据需另传与测试帧匹配的 STRUCTURE_MANIFEST。

准备 scene_split.json，三组必须非空、互斥，场景实际位于 TRAIN_DATA_ROOT：
  {"train":["scene_a","scene_b"],"calibration":["scene_c"],"validation":["scene_d"]}
用实际场景名替换示例。必须按场景划分，避免相邻帧泄漏。
正式 test 场景不参与结构训练、置信度训练或指导强度选择。

4. 训练独立结构头

2026-10-27：H0/H1 区域监督、结构诊断、best/last 与续训规则见 docs/idea8_structure_training.txt。
新训练默认仍为原 smooth_l1；region_balanced 必须显式启用，正式对照前先固定区域阈值。

以下均在服务器仓库根目录、已安装 requirements.txt 的环境运行。
路径全部由环境变量传入，不绑定服务器账户；不会启动原生成器训练。
先设置数据、划分和输出目录；默认兼容模式不需要时间单位/窗口。

  export TRAIN_DATA_ROOT=/your/dataset/train
  export SCENE_SPLIT=/your/config/scene_split.json
  export OUTPUT_DIR=/your/results/idea8_structure
  PHASE=structure bash train_scripts/train_idea8_structure_head.sh

若需固定窗口，再设置 STRUCTURE_MODE=fixed_window 及前述三个时间参数。
whb / SDE indoor 可直接运行 train_scripts/train_idea8_sde_indoor_whb.sh，默认依次完成两阶段；
配套 test_scripts/test_idea8_sde_indoor_whb.sh 使用指定 Stage3 生成器、timestep=500。
阶段 A 以正常光图像的固定软边缘作标签，训练结构预测器；不乘预测置信度。
结构头初始编码通道为 32/64/96，输出 1/2 高分辨率融合后的两尺度边缘。

阶段 B 在 calibration 场景上冻结结构分支，仅训练置信度头：

  PHASE=confidence \
  INIT_STRUCTURE_CHECKPOINT=/your/results/idea8_structure/checkpoint_last.pt \
  OUTPUT_DIR=/your/results/idea8_confidence \
  bash train_scripts/train_idea8_structure_head.sh

置信度标签为 exp(-abs(预测边缘-正常光边缘)/tau)，默认 tau=0.1。
训练完成这一阶段不代表已证明置信度可靠，仍需检查 validation 场景结果。

默认 AdamW、lr=0.0001、10 epochs、每卡 batch=4、num_workers=0、seed=42。
EPOCHS/BATCH_SIZE/LEARNING_RATE/CONFIDENCE_TAU/NUM_WORKERS/SEED 支持环境变量覆盖。
附加 Python 参数可放在脚本末尾，例如 --base_channels 16；CPU 检查设置 DEVICE=cpu。
whb 包装脚本默认 NUM_PROCESSES=2、CUDA_VISIBLE_DEVICES=0,1，全局 batch=8，学习率仍为 0.0001。
通用脚本默认 NUM_PROCESSES=1；双卡可设 NUM_PROCESSES=2 CUDA_VISIBLE_DEVICES=0,1。
单卡示例：NUM_PROCESSES=1 CUDA_VISIBLE_DEVICES=0 bash train_scripts/train_idea8_sde_indoor_whb.sh。
若希望双卡全局 batch 仍为 4，设置 BATCH_SIZE=2。结构和置信度依次执行，每个阶段各自使用两卡。
Bash 自动用 python -m torch.distributed.run 启动本机进程，不要再在外层套 torchrun/accelerate。
CUDA 使用 NCCL，一进程一卡；CPU/Gloo 用于本地双进程回归。脚本实际启动前检查可见 GPU 数量。
DDP 的 num_workers>0 时强制 spawn 创建数据 worker，避免在 NCCL 初始化后 fork 通信状态。
训练数据按 DistributedSampler 分片，每轮 set_epoch；样本数不能被卡数整除时补齐少量重复样本，
训练 loss 按实际处理样本数汇总。验证按 rank 分片不补齐，每个样本只计一次，允许某 rank 无验证样本。
仅 rank 0 写配置、日志和 checkpoint；所有 rank 的 RNG 随 checkpoint 保存，推理仍单卡加载无 module. 前缀的权重。
恢复训练使用同一 phase，EPOCHS 表示希望达到的总 epoch 数：

  PHASE=confidence RESUME_FROM_CHECKPOINT=/your/results/idea8_confidence/checkpoint_last.pt \
  OUTPUT_DIR=/your/results/idea8_confidence EPOCHS=20 \
  bash train_scripts/train_idea8_structure_head.sh

RESUME_FROM_CHECKPOINT 与 INIT_STRUCTURE_CHECKPOINT 互斥。续训恢复优化器、epoch
和随机状态；改变阶段用 INIT。配置不兼容时报错。恢复精度为 epoch 边界。
完整续训须保持 world_size、每卡 batch、num_workers、seed、设备类型不变，不能把旧单卡状态当双卡精确恢复。
改变卡数可用 PHASE=structure INIT_STRUCTURE_CHECKPOINT=旧结构权重 OUTPUT_DIR=新目录，仅继承权重，从 epoch 0 重新建优化器。
置信度阶段可从任意卡数训练完成的结构权重初始化；同样不继承结构阶段优化器或步数。
输出 checkpoint_last.pt、run_config.json、metrics.jsonl；日志在本地，不依赖 W&B。

终端 step 进度默认 LOG_INTERVAL=50（Python 参数 --log_interval 50，须为正整数）：
  LOG_INTERVAL=20 bash train_scripts/train_idea8_sde_indoor_slpchen.sh
每个 epoch 的训练和验证分别在开始、首 batch、每 N 个 batch、最后一个 batch 输出，立即 flush。
仅 rank 0 输出 phase、stage、epoch、step/总步数、百分比、当前/累计 loss、阶段耗时、秒/步和预计剩余时间。
step 按当前阶段的 batch 计数，每个 epoch 重置；DDP 训练的一个 step 是所有 rank 各处理一个 batch。
loss_rank0/avg_loss_rank0 只反映主卡的当前/累计样本；epoch 末原有 JSON 仍是全卡汇总，metrics.jsonl 格式不变。
ETA 只估计当前阶段的剩余时间，验证进度仅为主卡所分到的批次；不增加循环内通信，兼容验证样本数不均匀。
指标/RNG 汇总、checkpoint 保存前后、等待其他 rank 和 epoch 完成也有独立提示。
这是 step 进度，不是定时心跳；若数据读取或单步很慢，会等该步完成才更新。
续训允许改变日志间隔。正在运行的旧进程不会自动更新；保存成功后重启并指定 PHASE/RESUME_FROM_CHECKPOINT。

  export PRETRAINED_MODEL_NAME_OR_PATH=/your/models/stable-diffusion-2-1-base

  GUIDANCE_STEPS=1 \

  OUTPUT_DIR=/your/results/idea8_guided MIXED_PRECISION=fp32 \

先在 validation 上试 1 步，再比较 2/3 步；参数是实现初值，并非验证过的最优值。
公平对比 baseline/guided 时固定数据、generator checkpoint、seed、prompt、
timestep、精度、event_lora_targets、普通 LoRA 激活组和原事件 active bins。

关键默认值（新通用脚本）：
  GUIDANCE_STEPS=0；GENERATOR_TIMESTEP=500；IMAGE_SIZE=256；SEED=42
  EVENT_LORA_VARIANT=residual_cross_attn；EVENT_LORA_TARGETS=auto
  EVENT_LORA_MOD_CHANNELS=64；LORA_RANK=4；EVENT_LORA_MODULATION_SCALE=0.1
  UNET_LORA_PARTS=none；DECODER_REFINEMENT_ENABLED=0
  CLORA_EVENT_ACTIVE_BINS=5；RGB_EVENT_ACTIVE_BINS=5
  MIXED_PRECISION=fp16；CUDA_VISIBLE_DEVICES=0；SAVE_IMAGES=0
  GUIDANCE_LR=0.01；GUIDANCE_TRUST_RADIUS=0.03
  GUIDANCE_PROTECTION_MODE=quadratic
  GUIDANCE_LAMBDA_LOW=1.0；GUIDANCE_LAMBDA_KEEP=0.5；GUIDANCE_LAMBDA_RANGE=1.0
  GUIDANCE_MAX_LOW_CHANGE=0.02；GUIDANCE_MAX_OUTSIDE_CHANGE=0.02
  GUIDANCE_MIN_CONFIDENCE=0.25；GUIDANCE_BACKTRACKING_STEPS=3
  GUIDANCE_TRACE_CANDIDATES=1；REPRODUCIBLE_INFERENCE=0

2026-10-26 软保护修订：先前 L1 权重 2/1 在服务器诊断的 104 个候选中，
保护成本均超过结构误差下降量，导致全部回退。当前默认改用零点附近平滑的二次惩罚，
并将权重设为 1/0.5；这只是本轮重测配置，不表示已经验证为最优超参数。
low/keep 的硬变化阈值仍按 L1 计算，不能把阈值错误地应用到平方误差上。
复现旧目标：GUIDANCE_PROTECTION_MODE=l1 GUIDANCE_LAMBDA_LOW=2 GUIDANCE_LAMBDA_KEEP=1。
基线与指导对照建议同时设置 MIXED_PRECISION=fp32 REPRODUCIBLE_INFERENCE=1：
关闭 TF32/快速 SDP 并控制 cuDNN；不支持严格确定性的 CUDA 算子只告警，不声称反向完全确定。
SAMPLE_MANIFEST 可指向 scene,frame_id 两列 CSV，选择验证子集；不会重编号或改变 seed+原索引。

targets=auto 继承 checkpoint，不强行改成 all；旧无 targets 元数据的权重按 v 处理。
新入口普通 LoRA 默认 none，7 个旧 baseline wrapper 则显式保留 down,mid,up。
旧 wrapper 的原数据/权重路径、legacy_fused/CGDRS、bin=1 等实验配置仍各自保留。

默认指标：PSNR(Y)、SSIM(Y)、LPIPS、整组 FID。
前三项逐图计算并按样本数汇总；FID 在整组预测与 GT 分布之间计算，不能逐图平均。
LPIPS 输入为 RGB [0,1]，由 PyIQA 处理。FID 沿用仓库 PNG 临时图像路径。
指标模型权重须在运行环境可用；依赖、下载或计算失败会抛错，不静默省略指标。
默认至少需要 2 张图；单图 smoke test 可显式 CALCULATE_FID=0。
小样本 FID 仅适合流程检查，不适合得出论文结论。
SAVE_IMAGES=1 保存预测/低光/GT；GUIDANCE_SAVE_DIAGNOSTICS=1 额外保存结构/置信度 tensor。
没有 GT 的实际部署可在脚本后加 --inference_only，显式关闭指标、保存输出；
此模式不读取 normal 图像。指导本身从来不接收 GT，也不据测试指标接受候选。

两种脚本都支持 DRY_RUN=1，仅打印参数，不检查远端文件是否存在，不启动计算。
实际运行会先检查路径，并调用 archive_run_context 保存运行上下文。

6. 输出和诊断

  idea8_summary.csv      总体 PSNR/SSIM/LPIPS/FID（默认四项齐全）
  idea8_per_image.csv    逐图前三项指标与结果路径
  idea8_scene.csv        逐场景前三项指标；FID 只在总体表中
  idea8_diagnostics.json 每图调用次数、接受步数、回退原因、目标变化、耗时
  idea8_diagnostics.jsonl 每完成一张图立即追加，保留中断前的诊断
  run_config.json        实际参数、LoRA targets、普通 LoRA 分组、scheduler/结构配置

有支持的指导还记录特征 shape、相对修正幅度、初始/最终损失、饱和比例、
平均置信度和有效支持比例。可选 diagnostics/<scene>/<frame>.pt 保存 S/C。
reason=no_event_support 表示事件有效支持为空；no_acceptable_candidate 表示
没有通过验收的进一步改进。两者均回退到有效结果，不强行锐化。

L_struct：C 加权 Huber 软边缘误差，Huber delta=0.1。
L_low/L_keep 的软保护默认使用均方差；低通外观与低可信区域权重分别为 1/0.5。
日志中的 low/keep 始终表示 L1 变化量，供 0.02 的硬预算检查；
penalty_low/penalty_keep 表示实际软惩罚，protection 为两者加权之和。
candidate_history 保存各步/回溯的学习率、raw/clamp 分项损失、相对特征变化、结构收益、
accepted 和 rejection_reasons；gradient_history 保存求梯度时的 raw 损失及梯度 RMS。
拒绝条件可区分 objective_not_lower、low_budget、keep_budget、nonfinite_candidate 和 nonfinite_objective。
L_range：raw VAE 输出超出显示范围的二次惩罚，避免依赖 clamp 导数。
投影约束的是 M*delta 相对 h0 各通道 RMS 的归一化幅度。
由于后段卷积/注意力会传播变化，空间掩码不代表输出变化绝对局部。
FP32 保存 delta/loss；FP16 后段反传采用 1024 的损失缩放后还原梯度。
数值异常或不合格候选不被接受；若初始生成器自身输出非有限值，则直接报错。
